AIの回答は、正しい。整理もされています。

なのに、読んでいて「なるほど！」と感じる説明と、そうでない説明があります。

この違いは、語彙の豊富さよりも、**話をどう組み立てるか**にあるのではないか。

そう考えて、上岡龍太郎氏の説明術に見られる論理構成を、AIエージェントのスキル **[Kamioka Logical Explainer](https://github.com/tamutamu/kamioka-logical-explainer)** にしてみました。

まずは、出力の違いを見てください。

## 同じ質問で比べてみる

質問は、**「なぜ人はマウントを取るのか？」** です。

以下は、実際の会話で得た「通常の回答」と「スキルの説明原理を与えた後の回答」からの抜粋です。読みやすさのため途中を省略しています。

### ① 通常のAI回答

> 人がマウントを取るのは、突き詰めると、**他人より優位に立つことで、自分の価値や立場を確認したいから**です。
>
> ただし、その心理にはいくつか種類があります。

回答では「劣等感」「承認欲求」「優越感」「不安・防衛」「支配欲求」の5つに分類したうえで、こう説明しました。

> Aさんは「私はこれができます」と言います。
>
> Bさんは「そんなことも知らないの？」と言います。
>
> 両者とも自分の能力を示そうとしていますが、決定的な違いがあります。
>
> - Aさん：**自分の能力を示すことで価値を確認する**
> - Bさん：**相手との上下関係を作ることで価値を確認する**

情報は整理されています。理由も分かります。

ただ、読んでいる側は、用意された答えを**受け取る**形です。

### ② Kamioka Logical Explainerの原理を使った回答

> 「そんなことも知らないの？」
>
> こういうことを言う人がいますね。
>
> 不思議な話です。相手が知らないことを教えたいなら、「それはこういうことですよ」で済むんです。
>
> ところが、わざわざ「そんなことも知らないの？」と付け加える。
>
> この一言、知識を伝えるうえでは何の役にも立ちません。
>
> では、何のために言うのか。
>
> **自分が知っていて、相手が知らない。その上下関係を確認したいわけです。**

さらに、こう続きます。

> テストで80点を取った人がいるとします。
>
> 周りがみんな60点なら、得意になります。ところが、周りがみんな95点なら、落ち込む。
>
> 本人の80点は、何も変わっていません。
>
> 変わったのは周りの人間だけです。
>
> つまり、**自分の価値を、自分自身ではなく、他人との比較で決めている**んです。

そして最後は、こう締めます。

> もっとも、マウントを取る人を見て「ああ、この人は自分に自信がないんだな」と見下して安心しているとしたら、それもまた、立派なマウントなんです。

同じテーマなのに、読後感が違いませんか。

なお、これは会話中の回答を比較したもので、モデルや条件を統一した性能実験ではありません。上岡龍太郎氏の実際の発言を引用したものでもありません。

## なぜ、伝わり方が違うのか

私がこのスキルで重視したのは、次の3つです。

| | 通常の回答 | スキルの説明 |
| --- | --- | --- |
| **入り口** | 結論から説明する | 「そんなことも知らないの？」という身近な一言から始める |
| **納得の作り方** | 原因を分類して伝える | 「80点は同じなのに、なぜ気持ちが変わる？」と考えさせる |
| **終わり方** | 要点をまとめる | 批判していた自分も同じことをしている、という逆説で終わる |

つまり、**答えを教えるのではなく、答えにたどり着く道筋を読ませる**のです。

これなら読み手は、専門用語を覚えなくても、具体例から自分で仕組みを理解できます。

通常の説明が悪いわけではありません。知識を手早く整理したいなら、分類や箇条書きは便利です。

一方で、**誰かに説明して納得してもらいたい場面**では、話の順番そのものが大きな意味を持つと感じました。

## その「話の順番」をスキルにした

[Kamioka Logical Explainer](https://github.com/tamutamu/kamioka-logical-explainer/blob/main/SKILL.md) では、説明を次の5段階で組み立てます。

1. **枕**：誰もが想像できる身近な場面から始める
2. **建前と物差し**：通説を問い直し、何を基準に考えるか示す
3. **具体的な裏付け**：説明に効く事実や数字を少数だけ使う
4. **本質への接続**：具体例から背後の仕組みを導く
5. **逆説で着地**：説教せず、気づきや余韻を残す

これは「上岡龍太郎風の口調」を真似するためのスキルではありません。**平易な言葉なのに筋が通って聞こえる、その構造**をAIに指示するものです。

ただし、もっともらしい話が事実とは限りません。スキルには、数字や発言を捏造しないこと、具体例一つから一般化しすぎないことも明記しています。

## インストールと使い方

Agent Skillsに対応した環境なら、次のコマンドで追加できます。

```bash
npx skills add tamutamu/kamioka-logical-explainer
```

その後は、例えばこう依頼します。

```text
Kamioka Logical Explainer を使って、
「なぜ会議は長くなるのか」を説明してください。
```

既存の解説文を書き直すこともできます。

```text
この文章を Kamioka Logical Explainer で書き直してください。
結論は変えず、身近な具体例から始めてください。

（ここに文章を貼る）
```
