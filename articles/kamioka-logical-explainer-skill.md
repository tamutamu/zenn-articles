「そんなことも知らないの？」

この一言には、知識を伝える以上の意味があります。

AIに「なぜ人はマウントを取るのか」と聞くと、劣等感、承認欲求、優越感など、もっともらしい理由が並びます。もちろん、それは役に立つ説明です。

でも、**理由を知ることと、理由に納得することは少し違う**。

この違いを埋めたくて、上岡龍太郎氏の説明に見られる論理の運び方を、AIエージェント向けスキル **[Kamioka Logical Explainer](https://github.com/tamutamu/kamioka-logical-explainer)** にしました。

まず、同じ質問に対する二つの回答を見てください。

## 同じ問いで、説明はどう変わるか

質問は、どちらも **「なぜ人はマウントを取るのか」** です。

以下は、ChatGPTで実際に交わした会話から、**冒頭・説明の中心・結び**を抜粋したものです。

### ① 通常の回答：理由を整理して教える

>

このあと、劣等感、承認欲求、優越感、不安・防衛、支配欲求の5つを整理します。

> Aさんは「私はこれができます」と言います。
>
> Bさんは「そんなことも知らないの？」と言います。
>
> 両者とも自分の能力を示そうとしていますが、決定的な違いがあります。
>
> - Aさん：**自分の能力を示すことで価値を確認する**

**結論を早く知りたいなら、こちらは十分に有用**です。分類も具体例もあり、単なる悪い回答ではありません。

**通常の回答**

人がマウントを取るのは、突き詰めると、**他人より優位に立つことで、自分の価値や立場を確認したいから**です。

ただし、その心理にはいくつか種類があります。

### マウントを取る5つの心理

| 心理 | 本人の内面 |
| --- | --- |
| ① 劣等感 | 自分に自信がないので、相手を下げて安心したい |
| ② 承認欲求 | 自分はすごい、優秀だと認めてほしい |
| ③ 優越感 | 他人より上にいること自体が気持ちいい |
| ④ 不安・防衛 | 自分が下に見られたり、軽視されたりするのが怖い |
| ⑤ 支配欲求 | 会話や人間関係の主導権を握りたい |

これらは重なることもあります。

### なぜ、わざわざ他人を下げるのか？

例えば、仕事で知識を披露する場面を考えてみます。

Aさんは「私はこれができます」と言います。

Bさんは「そんなことも知らないの？」と言います。

両者とも自分の能力を示そうとしていますが、決定的な違いがあります。

- Aさん：**自分の能力を示すことで価値を確認する**
- Bさん：**相手との上下関係を作ることで価値を確認する**

Bさんにとって重要なのは、知識そのものよりも「自分が上、相手が下」という関係です。

心理学では、他人との比較によって自分を評価することを「社会的比較」と呼びます。相手を下に置いて安心しようとする行動も、その一つとして理解できます。

### 自信がある人ほどマウントを取らないのか？

必ずしもそうとは限りません。

自信がある人でも、競争心が強かったり、上下関係を重視する環境にいたりすれば、マウントを取ることがあります。

ただ、**自分の価値を他人との優劣に依存していない人は、マウントを取る必要性が小さい**と考えられます。

### 私が特に重要だと思うこと

マウントを取る人は、必ずしも相手を嫌っているわけではありません。

むしろ、相手の能力を認めているからこそ、脅威を感じてマウントを取ることもあります。

つまり、マウントは相手の能力についての客観的な評価というより、**マウントを取る側の心理状態や価値観を反映している**場合があるのです。

一つ聞きたいのですが、今回気になっているのは、**職場などで知識や能力を使ってマウントを取る人**ですか？ それとも、日常的に何でも張り合ってくる人でしょうか？

この2つは、心理的な背景が少し違います。

**説明原理を適用した回答**

「そんなことも知らないの？」

こういうことを言う人がいますね。

不思議な話です。相手が知らないことを教えたいなら、「それはこういうことですよ」で済むんです。

ところが、わざわざ「そんなことも知らないの？」と付け加える。

この一言、知識を伝えるうえでは何の役にも立ちません。

では、何のために言うのか。

**自分が知っていて、相手が知らない。その上下関係を確認したいわけです。**

ここで一つ考えてみたいんです。

テストで80点を取った人がいるとします。

周りがみんな60点なら、得意になります。ところが、周りがみんな95点なら、落ち込む。

本人の80点は、何も変わっていません。

変わったのは周りの人間だけです。

つまり、**自分の価値を、自分自身ではなく、他人との比較で決めている**んです。

マウントを取る人にも、これと似たところがあります。

自分が賢いかどうかより、相手より賢いかどうかが大事なんです。

だから、相手が優秀だと面白くない。自分が知らないことを相手が知っていると、何とかして別の話題で勝とうとする。

もっと面白いのは、本当に自信のある人でも、マウントを取ることはあるということです。

ですから、単純に「劣等感があるから」と片付けるのも違うと思うんです。

自信がないから相手を下げる人もいれば、人より上にいること自体を楽しむ人もいる。

ただ、どちらにも共通することがあります。

**相手との上下関係が、自分にとって大きな意味を持っている。**

考えてみれば、妙な話です。

相手を馬鹿にしたところで、自分の知識が一つ増えるわけでもない。能力が上がるわけでもない。

相手を下げても、自分は一ミリも高くなっていないんです。

それでも高くなった気がする。

マウントというのは、結局、そういう錯覚を利用した自己満足なんでしょうね。

もっとも、マウントを取る人を見て「ああ、この人は自分に自信がないんだな」と見下して安心しているとしたら、それもまた、立派なマウントなんです。

**人間というのは、なかなか他人との背比べをやめられない生き物なんでしょうね。**

:::

## 何が違うのか

| 観点 | 通常の回答 | 説明原理を適用した回答 |
| --- | --- | --- |
| 入り口 | 結論と原因の分類 | 「そんなことも知らないの？」という一言 |
| 説明の進め方 | 理由を整理して提示 | 「なぜ余計な一言を言うのか？」から考える |
| 具体例の役割 | 原因の違いを示す | 比較によって自己評価が変わる仕組みを体感させる |
| 結び | 要点を整理する | 読み手自身にも問いが返ってくる |

私がこのスキルで増やしたかったのは、語気の強さでも名言らしさでもありません。

**読み手が「言われたから分かった」ではなく、「自分で気づいた」と感じるまでの道筋**です。

ただし、②にも弱点があります。「80点の人が周囲と比べる」例で説明できるのは、他人との比較までです。**そこからなぜ相手を見下す言動に出るのか**は、もう一段説明が必要です。

話がうまく聞こえることと、論理が完結していることは違います。この穴に気づけるかどうかも、スキルの品質を考えるうえで大切だと思っています。

## 上岡龍太郎氏の説明から、何を学んだのか

名前だけ借りて「上岡節で話して」と命令したわけではありません。

参考にしたのは、実際の発言が記録されている次のような場面です。

**① 複雑な話を、短い物差しに置き換える**

1990年の『EXテレビ』で上岡氏は、テレビの面白さを「素人が芸をするか、玄人が私生活を見せる」という二つの型で捉えました。長いテレビ論を、まず一つの対比で見渡せるようにしています。

出典：[日刊スポーツ・当時を知る記者の回想](https://www.nikkansports.com/entertainment/column/umeda/news/202306020001004.html) ／ [1990年の放送内容を紹介した記事](https://yutura.net/news/archives/95256)

**② 批判の対象を、曖昧にしない**

1991年3月28日の『EXテレビ』「占いを告発する」では、占い師という職業全体を嫌っているのではなく、他人の弱みを利用して金銭を得る行為を問題にしていました。

「占いが嫌い」では話が雑になります。「何を問題にするのか」を先に決めることで、議論の焦点がはっきりします。

出典：[文春オンライン：番組での発言を記録した記事](https://bunshun.jp/articles/-/64576?page=3)

この2例から私が抽出したのは、**ものごとを短い対比で捉え、判断基準を明確にしてから論を進める**という工夫です。

もちろん、二つの事例で上岡氏の話芸のすべてを説明できるわけではありません。以下の5段階は、発言の逐語的な再現でも、科学的に効果が実証された理論でもなく、**私なりに整理した文章設計の手順**です。

## スキルの中身は5段階

公開している [SKILL.md](https://github.com/tamutamu/kamioka-logical-explainer/blob/main/SKILL.md) では、次の順番を指示しています。

1. **枕**：誰でも想像できる場面から入る
2. **建前と物差し**：当たり前を問い直し、判断基準を示す
3. **具体的な裏付け**：説明に必要な事実や数字を少数使う
4. **本質への接続**：具体例から仕組みを導く
5. **逆説で着地**：説教ではなく、気づきを残す

ステップ名を見出しとして並べるのではなく、一続きの自然な話にすることも指示しています。

そして、**事実と推測を混同しない、例えの対応を崩さない、一例から一般化しすぎない**。これもセットです。

## 技術的な説明にも使えるか

例えば、コードレビューを説明するとき。

> 「レビューで指摘が10件も出ました。だから良いレビューだった」
>
> そう言われたら、少し考えたくなります。
>
> 指摘10件のうち、直すことで不具合を防げたのが1件。残り9件は好みの書き方だったとしたら、どうでしょう。
>
> 逆に指摘が1件でも、重大な権限漏れを防いだなら、その1件には大きな価値があります。
>
> **レビューの成果は指摘の数ではなく、何を防ぎ、何を良くしたかで測る。**
>
> 指摘が多いほど良いレビューなら、最も優秀なのは粗探しの得意な人ということになってしまいます。

これは**公開版スキルの設計方針に沿って、この記事用に作った応用例**です。実測比較ではありません。

技術解説、設計判断、提案資料など、**正しいだけでは足りず、相手に判断してもらう必要がある場面**で活用できると考えています。

## インストール

Agent Skillsに対応したエージェントには、[Skills CLI](https://www.skills.sh/docs/cli) から追加できます。

```bash
npx skills add tamutamu/kamioka-logical-explainer
```

例えば、次のように依頼します。

```text
Kamioka Logical Explainer を使って、
「なぜコードレビューが長引くのか」を説明してください。
身近な具体例から始め、判断の物差しを明確にしてください。
```

説明済みの文章を書き直す用途にも使えます。

```text
以下の文章を Kamioka Logical Explainer で書き直してください。
結論と事実は変えず、話の順番を改善してください。

（ここに本文）
```

## 比較を確かめるなら

上の実例は、スキルの効果を保証するものではありません。より公平に確かめるには、**同じモデル・同じ質問・同じ長さの条件**で、新しい会話を二つ用意し、一方だけに公開版の `SKILL.md` を与えてください。

「引き込まれるか」だけでなく、**結論の正しさ、例から結論への飛躍、事実の正確さ**も比べると、弱点まで見えてきます。題材や試行回数を増やさなければ、安定した改善とは言えません。
